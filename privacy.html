NOVAAI BACKUPS

Privacy policy

Last updated: 6 October 2026

NOVAAI Backups is a personal backup application operated by Jamal Aljaberi. This policy describes its intended operation. Configuration is in progress; scheduled backups have not yet been enabled.

Data the application handles

The application processes the owner's selected database exports, archived documents, knowledge notes and recovery configuration on the owner's Mac. It uploads encrypted backup data to the Google Drive account the owner authorizes.

It handles Google OAuth credentials and tokens, plus backup file identifiers, metadata and operational status needed to upload, verify, retain and restore backups.

Google permissions and their purpose

The requested Google Drive scope is https://www.googleapis.com/auth/drive.file. It permits access to files created by the application or explicitly authorized for it. The application uses this access to create its backup folder, upload and inspect backups, restore data, and remove backups according to the owner's configured retention policy.

This connection does not request Gmail, contacts or calendar access. The owner grants access through Google's authorization screen; the application does not collect the owner's Google password.

Encryption and credential storage

The planned backup process uses restic to encrypt data before rclone transfers it to Google Drive. File and folder metadata associated with the encrypted repository, its size and transfer activity remain visible to the storage provider.

Application credentials and recovery secrets are managed through 1Password and protected local runtime storage. A 1Password service-account bootstrap token is stored in macOS Keychain. Credentials and encryption keys are excluded from this website, public source code and ordinary application logs.

Use and disclosure

Data is used for personal backup, integrity verification, retention and recovery. Backup content is not sold, used for advertising, or submitted by this backup application to AI providers for model training or inference.

Google Drive stores the encrypted backup repository. 1Password stores configured credentials and recovery material. GitHub hosts this information website. These providers process service data under their own terms and privacy policies. There are no added analytics scripts, advertising scripts or application cookies on this site; GitHub may process normal hosting request data.

Retention and deletion

Backup retention will be set by the owner before scheduled backups begin. Removing a source document does not immediately erase its copies from older backups; those copies remain until the relevant backup data is removed under the retention policy.

The owner can stop future backups by revoking the Google connection and can remove existing backup data from Drive. Google Drive trash and provider retention rules may delay permanent deletion. Local staging files and recovery copies must be handled separately.

Revoking access

Visit Google Account connections, select NOVAAI Backups and remove its access. This stops future authorized API access but does not itself delete existing backups. To resume, the owner must authorize the application again.

Questions and policy updates

The operator is Jamal Aljaberi. General application questions or privacy requests can be raised through the project's GitHub issues. Issues are public: include no documents, account tokens or other private information. This page will be updated when the application's data practices change.
